# Модель безопасности

Продукт хранит чувствительное: связку «пожилой человек — его дети — распорядок дня».
Утечка распорядка (когда мама одна дома и когда не отвечает) — худший сценарий, защищаемся от него в первую очередь.

## Периметры

| Граница | Механизм |
|---|---|
| iOS → Supabase | anon key + **RLS на каждой таблице, default deny**; политика — членство в семье через `is_family_member()` (security definer) |
| Telegram → Worker | секрет в пути + заголовок `X-Telegram-Bot-Api-Secret-Token`, сравнение constant-time; `drop_pending_updates` при перевыпуске |
| RevenueCat → Worker | Bearer-токен, constant-time сравнение |
| Worker → Supabase | service role **только** в Wrangler-секретах; в коде клиента не существует |
| Worker → APNs | token-based auth (.p8 в секретах), JWT живёт ≤50 мин |

## Правила данных

- **Минимизация**: геолокации нет by design; телефоны родителей не собираем (Telegram user id достаточно); свободный текст мамы шифруется at rest (Postgres) и виден только семье через RLS.
- **Право на забвение**: `/stop` у родителя = реальное удаление его чек-инов и событий (обещано в текстах бота — юридическое обязательство). Удаление аккаунта ребёнка в приложении — App Review 5.1.1(v).
- **PII в логах запрещён**: Worker логирует id и коды ошибок, никогда — тексты сообщений.
- **Инвайты**: 10 символов base62 (~59 бит), одноразовая атомарная привязка (`bound_at is null → set`), TTL 30 дней, перевыпуск гасит старый код.
- **Идемпотентность против гонок**: `unique(parent_id, local_date)` на чек-инах и эскалациях — двойной cron-тик или дубль вебхука не создают дублей и повторных пушей.

## Отказоустойчивость честности

- **Delivery-gate**: эскалация стартует только если утреннее сообщение фактически принято Telegram; сбой сервиса = статус «сломались мы», а не «мама молчит». Ложная тревога по нашей вине — худший продуктовый инцидент, он же репутационный.
- 403 от Telegram (бот заблокирован) → `bot_state='blocked'` → ребёнку сервисный пуш «переподключим за минуту», эскалаций нет.
